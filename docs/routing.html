AI Consultants Smart Routing

The Smart Routing system automatically selects the most suitable consultants based on the question category.

Enabling

# Enable classification (required)
ENABLE_CLASSIFICATION=true

# Enable smart routing
ENABLE_SMART_ROUTING=true

# Minimum affinity to include a consultant (1-10)
MIN_AFFINITY=7

Affinity Matrix

Consultant-category affinity scores (scale 1-10) live in references/affinity.json — the single source of truth at runtime. Prior to v2.11.0 the matrix was hard-coded as nested case statements in scripts/lib/routing.sh; it was extracted to JSON to make customization possible without editing bash.

Highlights from the default matrix:

Legend:

  • 5-6: Medium match
  • 1-4: Poor match

Schema

{
  "version": "1.1",
  "default_score": 5,
  "general_score": 8,
  "known_consultants": ["Gemini", "Codex", "..."],
  "categories": {
    "CODE_REVIEW": { "Gemini": 7, "Codex": 10, "..." },
    "BUG_DEBUG":   { "..." }
  }
}

Lookup logic in get_affinity(category, consultant):

  1. If consultant is not in known_consultants → default_score
  2. Else if category is not in categories (e.g. GENERAL or unrecognized) → general_score
  3. Else → categories[category][consultant], falling back to default_score if missing

Custom Matrix Override

Override the matrix at runtime by pointing AFFINITY_FILE at a custom JSON file with the same schema:

AFFINITY_FILE=~/my-affinity.json ./scripts/consult_all.sh "your question"

This is useful for:

  • Tweaking scores for a specific project (e.g., favoring DeepSeek for algorithm-heavy codebases)
  • Disabling consultants for a category by setting their score below MIN_AFFINITY
  • Experimenting with new categories before upstreaming them

./scripts/doctor.sh validates the JSON schema and reports coverage gaps (consultants missing from a category).

The matrix is loaded once per shell and cached in memory — no jq overhead on subsequent calls.

Cost-Aware Routing (v2.3+)

When ENABLE_COST_AWARE_ROUTING=true, selected consultants use economy models for simple questions and can retry low-confidence responses with their premium model. Consultant selection itself continues to use the affinity matrix above.

ENABLE_COST_AWARE_ROUTING=true
COMPLEXITY_THRESHOLD_SIMPLE=3    # Score 1-3 = use economy models
COMPLEXITY_THRESHOLD_MEDIUM=6    # Score 4-6 = use standard models
                                 # Score 7-10 = use premium models

See COST_RATES.md for model pricing by tier.

For Hydrogen on the native API, economy and premium share the model ID gemini-4-hydrogen and differ by thinking effort: medium versus xhigh. Cost-aware requests carry the economy effort only in the request subshell; a valid low-confidence structured answer can escalate to the premium effort. Explicit GEMINI_REASONING_EFFORT pins win, and cache identity records the effective economy effort so it cannot be confused with a premium request.

An explicitly selected Carbon CLI model stays pinned. Automatic cost-aware routing and confidence escalation do not replace it with Hydrogen or another model. Its exact account inventory check still applies before dispatch.

Supported Categories

Pattern classification (scripts/classify_question.sh) checks the categories in the order below and returns the first match. Keywords are matched case-insensitively, mostly as substrings.

SECURITY

  • Vulnerabilities
  • Authentication
  • Authorization

Keywords (whole words): security, secure, vulnerab…, exploit…, CVE-…, XSS, CSRF, SSRF, SQLi, JWT, OAuth, auth/authn/authz, authenticat…, authoriz…, password, encrypt…/decrypt…, secret, sanitiz…; also injection, access token, API key. Checked first, because security questions often also say “fix”, “design” or “review”. Dependency, constructor, setter, field, property, method, interface and fault injection are design or testing terms, not security.

CODE_REVIEW

  • Code quality review
  • Best practices

Keywords: review, check, analyze … code, quality

BUG_DEBUG

  • Debugging
  • Error fixing
  • Troubleshooting

Keywords: bug, error, crash, fix, debug, problem, issue, not working, fails, exception, traceback

ARCHITECTURE

  • System design
  • Design patterns
  • Scalability

Keywords: architect, design, pattern, structure, microservic, monolit, scalabil, refactor, organiz, system design

ALGORITHM

  • Algorithms
  • Data structures
  • Complexity and performance

Keywords: algorithm, optimi, performance, complexit, O(, big-o, efficien, sort, search, data structure

QUICK_SYNTAX

  • Quick syntax
  • Snippets

Keywords: syntax, how to write, example of, snippet, one-liner

DATABASE

  • SQL queries
  • Schema design
  • DB optimization

Keywords: database, SQL, query, MongoDB, Postgres, MySQL, Redis, index, migration, schema

API_DESIGN

  • REST API
  • GraphQL
  • Endpoint design

Keywords: API, REST, GraphQL, endpoint, request, response, HTTP, webhook

TESTING

  • Unit test
  • Integration test
  • Test strategy

Keywords: test, testing, unit test, integration, mock, stub, coverage, TDD, BDD

GENERAL

  • Default for everything else

Classification Modes

Pattern-based (default)

CLASSIFICATION_MODE=pattern
  • Fast, no API call
  • Regex matching on keywords
  • Good accuracy for clear questions

LLM-based

CLASSIFICATION_MODE=llm
  • More accurate, at the cost of one small call
  • Uses the Claude CLI on the economy model, stateless and tool-free, bounded by CLASSIFICATION_TIMEOUT (default 30 s)
  • Falls back to pattern matching when Claude is unavailable, is the invoking host, or returns an unknown category

Usage Example

# Consultation with smart routing
ENABLE_SMART_ROUTING=true \
./scripts/consult_all.sh "How can I improve the security of my API?"

# Output:
# [INFO] Category: SECURITY
# [INFO] Smart routing for category SECURITY...
# [INFO] Selected consultants: Mistral Codex ...

API Functions

Functions are exported from scripts/lib/routing.sh:

source scripts/lib/routing.sh

# Get affinity
get_affinity "SECURITY" "Mistral"  # → 10

# Select consultants
select_consultants "SECURITY" 7    # → Enabled consultants with affinity ≥ 7

# Check recommendation
is_recommended "SECURITY" "Claude" 7 && echo "Recommended"

# Cost-aware model selection (v2.3)
get_cost_aware_model "codex" 2  # → Economy model when enabled
