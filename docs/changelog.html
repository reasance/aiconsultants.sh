[5.3.2] - 2026-10-21

Fixed

  • The report’s Coverage Union now says which of three things happened: the strategy makes no union (for example majority), the synthesis returned no points, or synthesis.json could not be read. The jq error is shown in the report and logged as a warning. Before, all three printed “coverage data unavailable”, and a jq error was silenced.

Privacy

  • Context chunking no longer leaves a copy of your files in ~/.cache/ai-consultants/chunks. Every large file it chunked was saved there as JSON, the copy was never read and never removed, and it piled up across runs. Chunks now travel only in memory. CHUNK_TEMP_DIR is still accepted but unused. Existing copies are not deleted automatically: remove ~/.cache/ai-consultants/chunks if you want them gone.

Testing

  • npm test now fails on any jq compile error during the run. test_all.sh puts a jq shim on PATH that records compile errors even when the caller discards stderr, the way the 5.3.0 Coverage Union bug hid. Runtime errors are not recorded. A sweep of the whole suite found no other compile error. Set AI_CONSULTANTS_TEST_NO_JQ_GUARD=1 to run without it.

Verification

  • PR #33 CI (jq 1.7) and the 5.3.2 release gate passed 35/35 suites plus lint with the jq guard active. Each regression test fails on the previous code.

[5.2.0] - 2026-10-19

Fixed

  • Host consultations (slash commands cd into the skill root) now build the context from the caller’s --context-root: the “Working Directory” and “Project Structure” sections previously described the ai-consultants installation instead of the user’s project. A home directory (or /) is never listed as the project tree.
  • GLM, DeepSeek, MiniMax (API mode) and custom API agents now receive their persona and the JSON response contract. They previously answered in prose, always landed in the fallback envelope, and could never contribute attributable coverage findings. MiniMax CLI receives the same contract through its native system channel instead of a Markdown-only instruction.
  • The semantic cache key includes each consultant’s model, transport, reasoning effort and persona settings, so a max_quality run can no longer be served answers cached by a fast run (and vice versa). Existing cache entries are ignored once.
  • Consultant answers are canonicalized by scripts/lib/response_canonicalize.jq before validation: wrapper keys, flat answers, nested or bare confidence (including GLM 5.3 Flash’s observed one-brace-short form), scores such as "8/10"/0.8/85/"high", string lists, and answer objects embedded in prose are repaired deterministically instead of being discarded; {"response": "<prose>"} becomes a fallback. Truncated or genuinely malformed JSON still fails closed (also when pretty-printed over several lines, or when an answer holds more than one JSON value) and now keeps a bounded metadata.raw_excerpt for diagnosis.
  • synthesis.json is canonicalized to a documented contract (scripts/lib/synthesis_canonicalize.jq): risk levels, action items, recommendation and string lists get stable types; timestamp and consultants_analyzed are local; every artifact (including failed-closed replacements) records synthesis_provider. A non-coverage strategy without a coverage list is no longer a structural failure.
  • A synthesis wrapped in a Markdown code fence, or surrounded by prose, is accepted instead of being replaced by the manual-review fallback.
  • The synthesis call is included in the session cost and budget checks (as a labeled estimate); the pre-synthesis budget estimate uses the actual synthesis model.
  • followup.sh: --session <id> restores the full original question (history now stores it); whole-panel follow-ups are recorded on the original session and point at the directory holding the new responses; non-consultant artifacts no longer appear as “Unknown” consultants in follow-up context.
  • --query-file questions are passed to the classifier, context builder and synthesizer through stdin rather than argv. CLIs that only accept the prompt as an argument (agy, vibe, kimi) fail fast with a clear diagnostic above the single-argument limit, and synthesis skips agy above it.
  • The runtime .env loader removes quotes from a quoted value followed by an inline marker such as # ai-consultants:pin, matching configure.
  • ai-consultants install from an npm/npx installation points the slash commands at the package root instead of the non-existent ~/.claude/skills/ai-consultants, and warns when running from the npx cache. When a complete curl | bash installation already exists there, it installs that installation’s own commands unchanged (so they match the scripts they run, and survive npm clearing its cache) and suggests scripts/install.sh --update when its version differs from the package.
  • A non-boolean flag value such as ENABLE_SEMANTIC_CACHE=TRUE no longer aborts the run after the consultants were queried.
  • API keys and request bodies reach curl through pipes, never argv (process list, 128 KiB per-argument limit on Linux) or a temporary file that a stopped query could leave behind; request bodies are built from the prompt on stdin, so API mode also works for prompts above that limit. doctor API connectivity checks pass the key the same way and are bounded by curl’s own time limit, so they work without GNU timeout.
  • The POSIX run_with_timeout fallback (no timeout/gtimeout) no longer blocks on an interactive terminal.
  • SYNTHESIS_STRATEGY from the environment is honored (below --strategy and a --mode default) and validated; {AGENT}_PERSONA and {AGENT}_PERSONA_NAME overrides take effect.
  • The cost-capped preset keeps an explicitly configured MAX_SESSION_COST and lowers only the stock $1.00 cap.
  • Cost-aware model overrides and escalation target the model variable of the active transport (Gemini API, Mistral Vibe). Escalation skips error and fallback envelopes, never re-asks the same model or leaves a maximum-tier target, and respects the budget. Smart routing honors cost-aware panel sizing.
  • The pattern classifier checks SECURITY first with word-bounded patterns (dependency, constructor or field injection is not a security question); LLM classification is bounded, stateless, tool-free, uses the economy Claude model and is skipped for a Claude host.
  • install.sh --uninstall refuses to delete a directory that is not an ai-consultants checkout; --branch without a value fails cleanly.
  • scripts/lib/grok_sandbox.sh is committed executable like the other libraries (the entry point no longer flips its mode at runtime).
  • doctor validates the affinity matrix routing actually loads and reports the synthesis provider that would be used.
  • Agent hosts: the SKILL.md contract takes the skill root from the directory that holds SKILL.md (Codex and Antigravity find the skill in ~/.agents/skills or <project>/.agents/skills, not only in ~/.codex/skills/~/.gemini/skills), says that a sandboxed shell needs network access, and notes that Codex rejects rm -f for the question-file cleanup. INVOKING_AGENT=agy (or antigravity) excludes the Gemini consultant like gemini. The README and setup guide no longer promise slash commands in Codex or the Gemini CLI (Codex has none; the Gemini CLI loads only .toml commands), document Antigravity (agy) as the Gemini host and mark the Gemini CLI as legacy.
  • The context’s “Optimization Details” table shows real file paths (src/cache.py, not src/cache/py).
  • A terminal Ctrl-C, which signals the whole process group, now continues with the answers received as documented. The interrupted poll sleep used to end the run with status 130 under set -e before the trap could continue it, and consultant CLIs kept running unobserved. Every consultant, escalation and synthesis job now ignores SIGINT explicitly (Bash 3.2 does so for background jobs, Bash 5 does not, and an adapter killed by the Ctrl-C orphaned its CLI), so only the run decides what a Ctrl-C means. A consultant CLI that the Ctrl-C ends itself (Node and Go CLIs restore SIGINT) is reported as stopped, not failed, and any unexpected exit while waiting stops every consultant still running.
  • The report’s Directory line names the caller’s project (--context-root) instead of the skill root.
  • Failure reasons name the real cause. run_query reports the stderr line that names an error, skipping CLI warnings and stack frames, instead of the first line (a Kimi config deprecation warning was shown as the reason). API consultants report the network cause (network error: could not resolve the host (DNS) (curl exit 6)), timeout, rate limit or server status instead of last HTTP: 000. An agy model-inventory failure states agy’s own message (for example bind: operation not permitted inside a sandbox) instead of “timed out, failed, or requires login”. Report reasons drop the log prefix, and when every failure is a network error the console and the report say so and mention the sandbox case.
  • agy can print its whole answer and then never exit: a live synthesis closed its conversation stream and idled for 16 minutes, so the no-timeout run waited forever. scripts/lib/agy_exit_guard.sh now runs every agy consultation and synthesis; when the output is one complete JSON object unchanged for AGY_EXIT_GRACE_SECONDS (default 60, 0 = off) it ends agy and keeps the answer. Prose or partial output still waits for agy to exit.

Changed

  • No generation timeout by default. Every consultant *_TIMEOUT, the maximum-tier QWEN3_MAX_QUALITY_TIMEOUT/DEEPSEEK_MAX_QUALITY_TIMEOUT, and SYNTHESIS_TIMEOUT/SYNTHESIS_TOTAL_TIMEOUT now default to 0 (no limit; previously 180/240/480/600 s). A call cut off by a client timeout was usually still billed while its answer was lost, and reasoning models (Gemini 4 Argon, Mistral Large 4) routinely approach the old limits. A positive value restores a hard limit; 0 also works for API transports (curl gets no -m). configure migrates the unpinned fixed values it generated through 5.1.2; pinned and custom values remain limits. Probe limits (model inventory, auth, health gate, doctor, LLM classifier) are unchanged.
  • The invoking host decides when to stop waiting. consult_all.sh polls its consultants instead of blocking on each in turn, logs Still waiting after Ns for: <names> every WAIT_HEARTBEAT_SECONDS (default 30, 0 = silent), and accepts a proceed request (touch <output dir>/.proceed, kill -USR1 <pid>, or a first Ctrl-C) that stops the current phase and continues with the answers received, and an abort request (touch <output dir>/.abort, SIGTERM/SIGHUP, or a second Ctrl-C) that ends the run with exit 130/143/129. Stopped consultants are reported as stopped (they count against quorum but not against reliability), their partial output is discarded, and they are excluded from synthesis and cost with a billing caveat; a proceed during synthesis skips it and the report says so. Escalation re-queries follow the same control: a proceed ends the escalation phase. A proceed that arrives after a phase has already finished does not stop the next one. Stopped work ends with its whole process tree (kill_process_tree), so no consultant CLI keeps running. Host commands and SKILL.md tell the invoking agent to run the consultation in the background, watch the heartbeat, and choose when to proceed.
  • Qwen defaults to Qwen3.8-Max (default, premium and max_quality on every Qwen transport; the Token Plan-only gate is removed) and Qwen3.8-Flash serves standard and economy. max_quality applies QWEN3_MAX_QUALITY_TIMEOUT (default 0, no limit) on every Qwen transport and adds xhigh effort only on the OpenAI-compatible wire. configure migrates unpinned qwen3.7-max and the retired qwen3.8-max-preview to qwen3.8-max. Both models are listed as unpriced (Token Plan quota).
  • GLM’s max_quality target is the GLM-5.3 flagship; GLM-5.3-Flash keeps premium and standard.
  • Mistral API mode (MISTRAL_USE_API=true) targets Mistral Large 4 (mistral-large-4, public preview) in every tier. configure migrates an unpinned mistral-large-3; pin it to keep the old target. Estimates use the list rate ($1.36/$4.18 per 1M), not the 50% preview price. One authorized query_mistral.sh smoke returned a structured answer with the provider-reported model mistral-large-4. The preview is absent from GET /v1/models, so that listing is not an access check. The Vibe CLI default (mistral-medium-3.5) is unchanged.
  • Gemini 4 Argon (GA 2026-10-13) is the Gemini default and maximum target: Gemini 4 Argon (High) on agy and gemini-4-argon on the API. Standard and economy keep Gemini 3.8 Flash (High/Low) on the CLI and gemini-3.1-pro-preview on the API. configure migrates an unpinned Gemini 3.8 Flash (High) (and the older Pro 3.1 / Flash 3.7 High defaults) and an unpinned gemini-3.1-pro-preview; pin them to keep the old targets. Estimates use the list rate ($4/$20 per 1M), not the introductory price through 2026-11-30. One authorized agy consultation smoke returned a structured, schema-valid answer with capability-probed identity (about 49 s for a short question). The API transport is offline-tested only; Google excludes Argon from the Free tier and the AI Pro plan.
  • Gemini API requests carry GEMINI_API_MAX_TOKENS (default 32768, was a fixed 4096) because thinking tokens count toward maxOutputTokens. gemini-4-argon accepts low|medium|high thinking and defaults to high, matching its CLI target. parse_google_ai_response joins every visible text part and skips thought parts instead of reading only the first part.
  • The Vibe economy tier uses mistral-medium-3.5 instead of devstral-small-2: Mistral retired Devstral and current Vibe configurations no longer define that alias.
  • Mistral API answers from reasoning models (Large 4) arrive as content chunks (thinking then text); parse_openai_response keeps only the text chunks instead of passing the whole array to the JSON contract. MISTRAL_API_MAX_TOKENS defaults to 16384 (was 4096) because the thinking chunks share that budget.

Sol gets high effort unless configured and rejects none/minimal before dispatch, like Astra. configure migrates exact unpinned gpt-5.5, gpt-5.6-sol and gpt-6-astra values (keeping the earliest migrated-from origin); pins, environment overrides and --set are kept.
